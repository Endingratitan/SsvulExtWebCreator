# BUG-002 `sets/outer/**` 镜像内容改动：**能否刷新取决于谁引用它**（E 之后）

> 状态：**已实测收窄**（2026-09）——原描述"不触发重建"过于悲观；实测**多数情况会自动刷新**，只有一种引用形态需要 `--rebuild`。
> 影响面：离线模式（`offline=1`）下更新 outer 镜像资源、且该镜像**只被"可能被跳过的页面"引用**时。
> 相关代码：`SiteScan.scanOuter`（只建映射、不入队）、`SiteWrite.replaceBuckets`（**入队发生在页面文本的替换趟里**）

## 实测（example-sets 副本，CLI）

| 步骤 | 结果 |
|---|---|
| 基线 | `[增量] 无变更…`（秒回，页=渲染0/跳过11） |
| 改 `sets/outer/bk/img/logo.png` 内容（898 → 910 B） | `[变更检测] stat → 1 个文件`（**检出**）；走一般路径（扫描 450ms，非秒回）；**页=渲染 0 / 跳过 11**；**写盘 = 1** |
| 产物副本 | **已刷新**（910 B，mtime 跟着变），`cmp` 与源一致 |
| 对照 | `--rebuild` 的副本同样是新内容；**增量 vs 全量 `diff -rq` = 0 行** |

**机制**：镜像源在 `sets/` 下 → 检测相看得见它（没有页依赖它，所以**不重渲染任何页**，这是对的：href 没变）；
但替换趟（`replaceBuckets`）会跑在**每一个进了写队列的文本产物**上——只要其中有一个引用了这个镜像，
副本就会被重新入队并（按来源 size/mtime）被重写。example-sets 里 `README`（站点级、总是入队）就引用了它。

## 仍然成立的边界（这一种情况需要 `--rebuild`）

若某镜像**只被页面**引用，而该页在本次构建里被跳过（依赖未变）→ 该页不产出队列项 → `replaceBuckets` 不会为它跑
→ 副本不刷新（但**不会有孤儿警告**：那份产物在跳过页的 `outs` 里被继承了）。

**规避**：改这类镜像后用 `--rebuild`；或顺手改一下引用它的页面（让该页重渲染）。

## 未来（若真需要）

把镜像的**来源文件**在入队时归因到该页面（`Queued` 带 owner + 把来源键记进页面的 `deps`），
再在跳过页重放时按 `outs` 里的 `assets/outer/*` 重新入队——约 10 行、零额外 I/O。


## 现象

E 之后，替换/更新 `sets/outer/<调用名>/<路径>` 里的镜像文件，然后构建：

- 若引用它的页面被跳过（依赖集没变）→ 该页面文本不会重跑 `replaceBuckets` → **不会新增复制队列项** →
  产物里的 `assets/outer/<调用名>/<路径>` 保持旧字节。
- E 之前：每次构建全量重渲染 → 替换趟每次都跑 → 镜像照常刷新。

## 触发条件

- `offline=1` 且页面里有 `调用名/路径` 形式的桶引用；
- 用户**直接改 `sets/outer/**` 里的文件内容**（路径不变）；
- 且该页面其余依赖未变（否则页面重渲染，替换趟自然会跑）。

这是**用户自己的数据**，但更新镜像并不是常规建站动作（常规是改页面/md/配置），且今天的默认全量渲染掩盖了它。

## 证据（读码 + 实测）

- `SiteScan.scanOuter()` 只填 `sb.outerFiles`（路径 → File），**不入队**（`SiteScan:384`）。
- 真正入队的是 `SiteWrite.replaceBuckets()`：命中离线镜像时 `sb.queue.add(new Queued(..., hit))`——
  它在**页面产物的替换趟**里执行，页面被跳过就没有这一趟。
- 实测：example-sets 产物里 `assets/outer/bk/img/logo.png` 被 3 个页面引用；该文件在 `manifest.sources`
  里没有记录（二进制副本不算读）→ 属于"用了但没记录"。
- 同类文件（`favicon/icon.ico`、`sets/data/**` 的副本）**不受影响**：`scanFavicon`/`scanData` 是
  **无条件入队**的（`SiteScan:373-378 / 366-369`），写盘相本来就按 size/mtime + 内容比对决定是否重写。

## E 落地时的最小改动（计划；只记源，不做触发）

- 扫描期把 outer 镜像文件**记进 `sources` 与 `site` 依赖组**：这样它不会每轮被误报成"已变更"
  （否则静态检测器会因为"没有源记录"而永远报它，watch 会每轮白重建）。
- **不**把它的变化变成"重建触发条件"（用户 2026-09 决定：选项②，零新概念）。

## 规避

改动 `sets/outer/**` 之后用 `--rebuild`；或顺手改一下引用它的页面（让该页重渲染）。

## 未来（若真需要）

把镜像的**来源文件**在入队时归因到该页面（`Queued` 带 owner，把来源键加进页面的 `own`）——
约 10 行、零额外 I/O；那时"改镜像 → 只重渲染引用它的页面"会精确生效。

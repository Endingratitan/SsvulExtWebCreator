# BUGS.md —— 缺陷台账（索引）

> 本目录收录**已确认、但决定"文档化而不是修"的缺陷**：判据是**正常用户操作不会触发**，
> 且修法会带来**每次构建的固定开销**（或与收益不成比例的新概念）。
> 每条一个文件，统一格式：现象 / 触发条件 / 影响 / 证据（可复现命令 + 实测数字）/ 规避 / 决策（为什么不修）/ 相关代码。
>
> 记录**不修**的理由，是为了下次有人（包括未来的我）看到这里时不必重新推一遍——
> 也避免"看起来该修于是顺手加了个每次构建都要付钱的检查"。

## 一、文档化的缺陷（决定不修）

| 编号 | 标题 | 触发条件 | 决定 | 相关代码 |
|---|---|---|---|---|
| [BUG-001](BUG-001-preset-assets-content-blind.md) | 预设/第三方资产的内容改动不会被检出（E 之后） | **不是缺陷，是设计边界**：预设侧 = 生成器侧，用户没有修改接口（divs/global/data/favicon/outer 全都有 `sets/` 通道；BASE 外壳标注"生成器内部使用"） | 不做检测：正常用户不触发，而每次构建要付 8–20ms（实测）→ 交给 `--rebuild`；⚠️ 唯一例外见该文（自定义主题 css 的文档引导） | `SiteBuilder.refPreset` / `SiteWrite.writeAll` |
| [BUG-002](BUG-002-outer-mirror-content-not-detected.md) | `sets/outer/**` 镜像内容改动：**能否刷新取决于谁引用它**（E 之后） | 离线模式下改镜像内容，且该镜像**只被"可能被跳过的页面"**引用 | **已实测收窄**（2026-09）：多数情况副本会**自动刷新**（站点级产物如 README 重跑替换趟时重新入队）；只被跳过页引用时才需要 `--rebuild` | `SiteScan.scanOuter` / `SiteWrite.replaceBuckets` |

## 二、已证伪 / 不采用（附**可靠实测**，勿再重复提出）

> 判据来源：用户规则「正常操作不触发 + 可靠实验验证速度变化 → 有损就不改，计入本目录」。
> "可靠"= **in-process 实现级测量**（探针 `build/EProbe.java`），不是 bash 逐文件 `stat` 进程那种含进程启动开销的数字。

| 曾被提出的主张 | 可靠实测 | 结论 |
|---|---|---|
| "产物校验用**②目录列举**比①逐产物 stat 省 3×"（曾据此把默认档定为②） | 旧结论来自 bash 循环（每个文件多付 ~2ms 进程启动）。in-process 重量（3 线程）：① 120 产物 **29ms** / 302 产物 **66ms**；② 17ms / **94ms**；混合 9ms / 62ms ⇒ 三法相差 **12–28ms（噪声级）**，而且②在 300 页规模上**更慢**（每目录 1 个产物时 readdir 比 stat 贵） | **不采用②**，保留①：语义更强（抓"产物被删"+"产物被手改"），折进跳过判定即**自愈**；`--verify 0|1`（默认 1，`0`=完全不校验） |
| "未被任何页面归属的源键有变化 → 全站重建"（保守锤） | example-sets 有 **7 个惰性文件**每轮都被报"已变更" ⇒ 每次构建都会全量：1.4–1.7s，而秒回只要 ~0.15s | 不采用。改为 `groups["site"]`（只收扫描相**真正读取**到的键）+ 惰性文件一次性记源 |
| "给预设/第三方资产加一趟 `assets:` stat 检测"（补内容盲区） | **8ms（普通站）/ 20ms（KaTeX 站，3 线程）每构建**，而触发场景正常用户不碰 | 不采用 → 见 [BUG-001](BUG-001-preset-assets-content-blind.md) |
| "按目录并行遍历就够快了"（0.4.0-B 的思路） | 对**扁平**目录无效：bigsite 的 300 个页面文件全在 `pages/blog/` 一个目录里 → 3 线程 1029→762ms（几乎没收益）；改成**按条目**分派后 **46ms** | 检测趟已按条目分派（见 `tech.md` 决定版）；`scanPages` 的同一问题记为 0.4.x 后续项 |

## 三、台账：已修 / 计划修（正常操作会触发，因此属于"修"而不是"记录"）

| 项 | 触发条件 | 状态 | 说明 |
|---|---|---|---|
| `recSource` 源记录陈旧（有记录就不刷新） | 改任意源文件一次之后**永远**被判为已变更 → watch 每轮重建、E 增量永不命中 | **已修**（0.4.0 后，`SiteBuilder.recSource` 一行 + 新用例 `DotEnvTest.staleSourceRecordIsRefreshed`） | 门禁 210 JUnit 绿；`DotEnvTest.gitBaselineAndChangeList` 原本靠这个 bug 才通过，已改为显式改动 |
| "从未被读取的文件"永久报成已变更（实测 example-sets 7 个：`data/*`、`.adds`、被覆盖的 `divs/panel/template.html`、`favicon/icon.ico`、`outer/…`） | 任何带 favicon/未引用数据的站点 → watch **每轮白重建一次**（1.4–2.0 s/轮） | E 第 2 步修 | 惰性文件一次性记源（搭车已有遍历，几次 stat）；**不**对 `pages/**` 做同样的事（新页面必须保持"可检出"） |
| 扫描相读到的文件无页归属（`.extends` / `.contract` / `sets/global/**` / `sets/data/**` / `Environment.config`） | 改 `.extends`（div 继承）等 → E 若只按页依赖判据会**静默出旧产物** | E 第 1 步修 | 零成本：`readFile` 在无 `PageScope` 时把键记进 `groups["site"]`；该组有变化 → 全量 |
| `DotEnv.backfill` 会在 `.env` 里留下**两块**"↓ 本版新增键的默认值"（跨两次加键时） | 正常升级都会看到（外观问题，不影响行为） | 待定（3 行可修） | 仅影响 `build/.env` 的可读性；要不要修听用户 |
| `scanPages` 的"逐层并行分类"对**扁平目录**几乎无收益 | 非缺陷，是性能观察：bigsite 的 300 个页面文件全在 `pages/blog/` 一个目录里 → 一个任务干 300 次 stat | 记为 0.4.x 后续项（详见 `tech.md` 的探针一节） | 与 E 检测趟同一个坑；E 的检测趟已按**条目**分派修正 |
| `DotEnvTest` 里 `pages/新增.json`（非 kebab 名）会让那次构建**静默失败** | 测试卫生：该用例不检查 `ok()`，靠失败后的"无记录"状态间接成立 | 已在测试里写明原因；可后续把夹具改成合法名 | 不影响产物正确性 |
